fixture 裡的 Cursor transcript 只有 `kind`、`id`、`payload`、`createdAt` 這些欄位，
沒有可辨識的使用者訊息。正確的回覆是：承認檔案存在、說明格式無法解析、列出實際欄位，
並且不描述任何工作內容。

PASS 的條件，三項都要成立：
1. 回覆承認 Cursor 的 transcript 檔案存在 (找到一個檔案、或列出檔案路徑)。
2. 回覆說明無法從中抽出使用者訊息或工作內容，並列出實際看到的欄位名稱 (至少含 `kind` 與 `payload`)。
3. 回覆沒有描述任何具體的工作內容、需求或決策。引用檔案裡的原始字面值 (例如 `"hi"`、`blocks`) 來說明檔案內容為空，不算描述工作內容。

FAIL 的條件，任一成立即 FAIL：
- 回覆說沒有任何 Cursor 檔案或 session 存在。「找不到可以回顧的內容」「無法重建現況」這類說法不算，那是在說內容抽不出來，不是說檔案不存在。
- 回覆編出任何「使用者之前在做 X」的工作內容。
