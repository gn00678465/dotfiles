# Recall

Extract the user's requests from local session files and turn them into a
current-state brief. All data is read locally. Nothing is uploaded.

## Process

1. **Lock the scope.** Settle three things before you run anything.
   - Window: default is the last 7 days. When the user says "all", pass `--days 0`. Never shrink "all" to the last N days silently.
   - Project: default is the current git root. Use `--project <path>` or `--all` only when the user says so.
   - Topic: when the user names one, add `--grep <keyword>`. The flag repeats.
   - State the scope back to the user in one sentence.
2. **Run the script.** It is `scripts/recall_sessions.py` in this skill's directory. It uses only the Python 3 standard library.

   ```sh
   python3 <skill-dir>/scripts/recall_sessions.py                      # current project, last 7 days, all sources
   python3 <skill-dir>/scripts/recall_sessions.py --days 30 --grep neovim
   python3 <skill-dir>/scripts/recall_sessions.py --source codex --all --format json
   ```

   When the output is long, add `--limit` or `--grep` first, or switch to `--format json` and filter with a tool.
3. **Read the output.** Each session is one block.
   - Skip the current session. Its content is this request.
   - "User messages" are the source of the requests. "Last assistant text" is the state when that session ended.
   - `ai-title` is a title generated by Claude Code. Use it to sort sessions quickly. Do not treat it as a conclusion.
   - When the last user message of a session has no matching completion reply, list it as an open item.
4. **Read the raw file when you need detail.** The output gives each session's file path. Read only the relevant region.
   When the answer depends on what the agent actually did (tools run, files changed), read the raw file. Do not rely on the summary alone.
5. **Return the brief.** Follow the output format below. Stop at the brief. Do not start the work.

## Output format

- **Status**: at most 5 bullets. What this work is and where it stands.
- **Decisions**: settled choices, one line each.
- **Open items**: at most 5 bullets.
- **Next step**: one concrete action.

Cite the source and the first 8 characters of the session id on each item, for example `[claude 5ac177cb]`.
When no session matches, say so and report the scope you searched.

## Script arguments

| Argument | Meaning |
| --- | --- |
| `--source claude\|codex\|cursor\|all` | Source. Default `all` |
| `--project <path>` | Project path, repeatable. Default is the current git root or cwd |
| `--all` | No project filter |
| `--days N` | Only sessions whose file mtime is within the last N days. `0` means no limit. Default 7 |
| `--grep <text>` | Keyword filter, repeatable, case-insensitive. Any match keeps the session |
| `--format markdown\|json` | Output format. Default `markdown` |
| `--include-subagents` | Include subagent sessions |
| `--limit N` | Maximum number of sessions to print |
| `--max-messages N` | User messages kept per session. Longer sessions keep the head and tail |
| `--claude-home` / `--codex-home` / `--cursor-home` | Override the source directories. Defaults read `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, and `~/.cursor` |

## Filtering rules

- The time window uses file mtime, not the timestamps inside records.
- Subagent files (`subagents/agent-*.jsonl`) and `isSidechain` records are skipped by default.
- Claude Code user records contain a lot of text that the user did not type. The script drops segments that start with these tags:
  `<command-message>`, `<command-args>`, `<local-command-caveat>`,
  `<local-command-stdout>`, `<task-notification>`, `<agent-message>`, `<system-reminder>`,
  `<tool-use-id>`, `<bash-stdout>`, `<bash-stderr>`, plus `isMeta` and compact-summary records.
  A `<system-reminder>` block attached after a real message is cut off. The text before it stays.
- A slash-command segment that contains `<command-name>` becomes one user message, for example `/herdr <args>`.
  `<command-args>` is what the user typed. When args are empty, only the command name is kept.
- `<bash-input>` and `<pasted_content>` are the user's own input. They are kept.
- In Claude Code, one assistant response is split over several rows that share `message.id`. Turn counts are deduplicated by it.

## Source status

| Source | Path | Status |
| --- | --- | --- |
| Claude Code | `~/.claude/projects/<slug>/<sessionId>.jsonl` | Verified locally (2.1.278) |
| Codex | `$CODEX_HOME/sessions/**/rollout-*.jsonl`, `archived_sessions/` | Implemented from the Codex record format, not verified locally |
| Cursor | `~/.cursor/projects/<slug>/agent-transcripts/<uuid>/<uuid>.jsonl` | Path rule only. Fields not verified |

When a Cursor record does not match the expected format, the script does not crash.
It prints one warning that lists the fields it actually saw.
Report those fields to the user. Do not guess the content.
